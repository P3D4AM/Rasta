# گزارش سازگاری نسخهٔ نصب‌شده 3.1.16.169.0303 با سورس 3.1.18.187

> سند ۰۹ — تحلیل ریسک تفاوت نسخه‌ها و سازوکارهای سازگارسازی IdealBridge

## ۱. وضعیت و روش

| مورد | مقدار |
|---|---|
| نسخهٔ نصب‌شدهٔ واقعی Ideal CRM | **3.1.16.169.0303** (محیط مالک — بدون دسترسی مستقیم در این مأموریت) |
| نسخهٔ سورس دیکامپایل‌شده | **3.1.18.187** (بستهٔ filebin در `ideal/` مخزن) |
| منبع حقیقت ساختار دیتابیس سورس | `Models/CRMTabel.ssdl` (۶۳۳ EntityType) + کاتالوگ ۵۹,۱۲۴ دستور SQL (`CRM__Update_187.exe`) |
| دسترسی به دیتابیس نصب‌شده | **Blocked** — اطلاعات Instance/دیتابیس/حساب هنوز ارائه نشده |

**نتیجهٔ صادقانه:** تطابق دقیق ساختار دیتابیس 3.1.16 **تأیید نشده و تأییدناپذیر تا لحظهٔ اتصال واقعی است** — و IdealBridge دقیقاً برای همین طراحی شده: حدس نمی‌زند، در زمان راه‌اندازی می‌کاود و سازگار می‌شود.

## ۳. استراتژی سازگارسازی IdealBridge (چه کار شده)

### ۳.۱ کد، صفحه‌بندی را از SP نمی‌گیرد
صفحه‌بندی همهٔ endpointها با `OFFSET/FETCH` **خود IdealBridge** روی SELECT پارامتری مستقیم (Keyset `afterId` یا `page/pageSize`) انجام می‌شود — وابسته به پارامترهای SP نیست که در 3.1.16 احتمالاً نیست.

### ۳.۲ مسیر Table پیش‌فرضِ پایدار
حالت `Table` روی ستون‌های هسته‌ای است که از نسخه‌های 2.2 وجود داشته‌اند. این مسیر، مسیر اطمینانِ حداقلی برای 3.1.16 است.

### ۳.۳ کاوش امضا پیش از استفاده از SP
`SchemaProbe` امضای هر SP را با `sys.parameters` با امضای مرجع 3.1.18.187 مقایسه می‌کند:
- مطابق → حالت `Sp` برای آن موجودیت (خروجی غنی).
- متفاوت/ناموجود → خودکار `Table`.

### ۳.۴ گسترش‌پذیری فهرست ستون‌ها
`SchemaProbe.RequiredTableColumns` فهرست ستون‌های «لازم برای حالت Table» است. اگر کاوش واقعی ستونی را مفقود گزارش داد، دو راه:
- آن ستون از DTO حذف/اختیاری می‌شود (ستون‌های اختیاری در فهرست علامت‌گذاری و در نسخهٔ بعد قابل‌تنظیم‌اند)؛
- یا همان موجودیت روی SP قابل استفاده می‌ماند.

### ۳.۵ ابزار استخراج مستقل
`tools/IdeaSchemaDump` گزارش کامل جداول/ستون‌ها/کلیدها/SPهای دیتابیس واقعی + مقایسهٔ خودکار با انتظارات را تولید می‌کند — این گزارش باید در استقرار واقعی برای نهایی‌سازی این سند اجرا و ضمیمه شود.

## ۴. چه چیزهایی قطعاً در 3.1.16 قابل تضمین نیست (تا کاوش واقعی)

1. وجود/امضای دقیق SPهای `ApispSelect*` (به‌ویژه پارامترهای صفحه‌بندی و Center).
2. ستون‌های افزودهٔ جدید: `cmpOfficial*`، `Tsp*`، `cmpCampaignIds`، محتوای JSON `cmpFOInfo`.
3. جداول جدید بین دو نسخه (کاتالوگ V7→V8 شامل CREATE PROC بازنگری‌شده و جداول کمکی مانند `CrmCompanyCampaign` است).
4. معناشنسی میدان‌ها (مثلاً اینکه `IsAdmin` رشتهٔ True/False است — در 3.1.18 چنین است؛ IdealBridge خوانندهٔ «bool-like» امن دارد).

## ۵. برنامهٔ اقدام برای محیط واقعی (چک‌لیست ۱۰ دقیقه‌ای)

```powershell
# ۱) با حساب فقط-خواندنی، گزارش ساختار را بگیرید:
dotnet run --project tools/IdeaSchemaDump -- --connection "<از سند ۰۵>" --out schema-report.json

# ۲) سرویس را بالا بیاورید و حالت‌ها را ببینید:
Invoke-RestMethod -Uri "$base/health/db" -Headers @{ "X-API-Key" = $tok }

# ۳) اگر چیزی Blocked بود:
#    - TablesMissing → دیتابیس اشتباه انتخاب شده یا نسخهٔ بسیار متفاوت
#    - ColumnsMissing → گزارش را برای ما بفرستید تا فهرست ستون‌های لازم تنظیم شود
#    - SpUnavailable → مشکلی نیست؛ حالت Table خودکار فعال می‌شود

# ۴) تست دود (smoke):
Invoke-RestMethod -Uri "$base/api/v1/companies?pageSize=10" -Headers @{ "X-API-Key" = $tok }
```

## ۶. جمع‌بندی ریسک

| ریسک | سطح | کاهش‌دهنده در IdealBridge |
|---|---|---|
| SPهای 3.1.16 با 3.1.18 فرق دارند | بالا | کاوش امضا + مسیر Table پیش‌فرض |
| ستون‌های جدید در 3.1.18 در 3.1.16 نیستند | بالا | DTO بر ستون‌های هسته؛ ستون‌های enrichment فقط در حالت Sp |
| تغییر معناشنسی داده بین نسخه‌ها | متوسط | نگاشت صریح + خواننده‌های امن bool-like/date-like |
| جدول‌های حذف/تغییرنام‌یافته | پایین | کاوش + گزارش Blocked دقیق به‌جای خطای مبهم |

**نتیجه:** IdealBridge بدون فرض یکسانی نسخه‌ها کار می‌کند؛ سازگاری نهایی با اجرای `IdeaSchemaDump` و `/health/db` روی محیط واقعی **قطعی** می‌شود.

# نقشه راه رستا (Rasta Roadmap)

> سند تصمیمات فنی — با پیشرفت پروژه به‌روز می‌شود

## اهداف محصول

- CRM تجاری بالغ: سبک، مدرن، فارسی/RTL-First
- حذف کامل میراث نسخه قدیمی (۹ jQuery، دو نسل Kendo، Bootstrap ناتمام، سه کتابخانه نمودار موازی)
- امنیت از روز اول — بدون تکرار بدهی‌های CRMIdeal
- آماده برای SaaS/چند-مستأجری در آینده

## پشته فناوری (تصمیم نهایی — پیاده‌سازی‌شده)

| لایه | انتخاب رستا | جایگزینِ قدیمی |
|---|---|---|
| زبان | TypeScript (سرتاسر استک) | C# / .NET FW 4.7 |
| فریم‌ورک | Next.js 16 App Router | ASP.NET MVC 5 |
| API | Route Handlers (REST) | Web API 2 |
| ORM | Prisma (code-first + مهاجرت) | EF5 Database-First (۷ EDMX!) |
| دیتابیس | SQLite (توسعه) → PostgreSQL (استقرار) | SQL Server |
| UI | Tailwind 4 + shadcn/ui — RTL، وزیرمتن | Kendo ×۲ نسل + Bootstrap 3/4 |
| نمودار | Recharts | Highcharts + Chart.js + CanvasJS |
| Auth | jose JWT + کوکی HttpOnly + scrypt | SimpleMembership |
| تقویم | جلالی بومی (`src/lib/jalali.ts`) | تقویم شمسی/قمری jQuery |

## نگاشت هسته دامنه (CRMIdeal → رستا)

| نسخه قدیم | رستا (MVP فعلی) |
|---|---|
| CrmCompany / CompanyPersons | Company / Contact |
| CrmProjects (فرصت‌ها) | Deal (کانبان فروش) |
| WSOrder / WSPreOrder | SalesOrder / Quotation (+ Payment) |
| Rolls / UsersPermission | Role / RolePermission (ماتریس دسترسی) |
| Cartables | Tasks کارتابل + Activities |
| Setting Area | Setting |
| WareHouse / WareHouseMovement Area | Warehouse + StockLevel + StockMovement (رسید/حواله/انتقال/اصلاح) |
| BuyOrders Area | PurchaseOrder (+Item) — سفارش تا رسید انبار |

## وضعیت فازها

- ✅ **فاز ۰ — زیرساخت:** مخزن گیت (main + develop)، دیکامپایل کامل ۸ اسمبلی (~۹ هزار فایل)، مستندات
- ✅ **فاز ۱ — هسته CRM (MVP):** Auth + RBAC، داشبورد KPI، شرکت‌ها، مخاطبین، فرصت‌ها (کانبان)، فعالیت‌ها، کارتابل وظایف، محصولات، پیش‌فاکتور→سفارش، پرداخت، کاربران/نقش‌ها، گزارش‌ها، داده دموی فارسی — E2E تست‌شده
- ✅ **فاز ۲ — انبار و خرید:** انبارها (پیش‌فرض/غیرفعال‌سازی نرم)، موجودی و گردش کالا (رسید/حواله/انتقال/اصلاح — تراکنشی)، کارت کالا، سفارش خرید (پیش‌نویس→سفارش→دریافت)، اتصال خودکار صدور/لغو فاکتور فروش به موجودی — E2E تست‌شده
- ✅ **فاز ۳ — مالی:** خزانه (درخت گروه‌ها + اسناد دریافت/پرداخت + مانده + گردش کار تایید)، بانک‌داری (بانک→شعبه→حساب با شماره کارت/شبا)، پرداخت آنلاین (تنظیم درگاه زرین‌پال/ملت/پارسیان + جریان پرداخت + لیست تراکنش) — E2E تست‌شده
- ✅ **فاز ۴ — پروژه‌ها و کاربران (از سورس واقعی):** پروژه/مذاکره با نتیجه‌های وضعیت و آرشیو خودکار، تعاریف پایه، بازسازی کامل کاربران (سمت/دپارتمان/امضا/ساعت ورود/ماتریس فرم×اکشن)
- ✅ **فاز ۴.۵ — بازسازی عیناً اسکیمای دیتابیس:** ۳۹۶ جدول با نام/ساختار اصلی (بخش ۱ @@map کامل + بخش ۲ کاتالوک ۳۵۴ مدل) + کاتالوگ مستند ۶۳۳ جدول + ۳۴۳۸ SP — پایه سیم‌کشی ماژول‌های بعدی
- 🟡 **فاز ۵ — زیرساخت تست + تعاریف پایه (ApiBaseInfo):** زیرساخت کامل راه‌افتاد — Vitest (واحد ۱۴/۱۴ + یکپارچه‌سازی ۳۵/۳۵ روی سرور واقعی و DB آزمایشی ایزوله) + Playwright (E2E ۱۰/۱۰) + CI (۴ کار موازی) + اسکریپت‌های `test/test:unit/test:integration/test:e2e`. اولین گروه ApiBaseInfo (جغرافیا: کشور/استان/شهر — ۱۲ اکشن از ۲۳۳) با الگوی قرمز→سبز کامل بازسازی و TESTED شد (قرارداد از دیکامپایل + متن SP + satellite fa-IR؛ ماتریس کامل ۲۳۳ اکشن: `docs/parity/apibaseinfo-matrix.md`). باقی‌مانده: گروه‌های P1..P6 (۲۲۱ اکشن ANALYZED) طبق اولویت وابستگی.
- ✅ **انتشار توسعه‌ای ویندوز (v0.3.0-dev.1 — خارج از فازها):** بستهٔ قابل اجرای ویندوزی از وضعیت فعلی develop ساخته و منتشر شد (Next.js standalone + Node.js ۲۴ LTS همراه بسته + SQLite مستقل + اسکریپت‌های Start/Stop/Install سازگار با PowerShell 5.1 + راهنمای فارسی) — برای بررسی دستی مالک؛ ساخت تکرارپذیر با `release/build-release.mjs`؛ تست بسته ۲۶/۲۶ PASS (معادل لینوکسی — `NOT VERIFIED ON WINDOWS` صادقانه ثبت شد).
- ⬜ **فاز ۶ — ارتباطات:** پیامک (۱۵+ درگاه)، ایمیل، ربات تلگرام
- ⬜ **فاز ۷ — منابع انسانی:** مرخصی، حاضری (QR)، مکان‌یابی GPS
- ⬜ **فاز ۸ — گزارش‌ساز پیشرفته + فرم‌ساز پویا (DyForms)**
- ⬜ **فاز ۹ — یکپارچه‌سازی مالی (سپیدار/هلو/...) + سامانه مودیان**
- ⬜ **فاز ۱۰ — ماژول AI:** مدیریت Providerهای LLM، کتابخانه Prompt، سهمیه Token کاربران
- ⬜ **فاز ۱۱ — سخت‌سازی، تست‌های خودکار، داکر و انتشار اولیه**

## نتیجهٔ فاز صفر — خط مبنا و ترتیب وابستگی‌محور فازها (۲۰۲۶-۱۰-۲۶)

ممیزی کامل در `docs/parity/` انجام شد (ماتریس قابلیت، فهرست‌وارسی نسخهٔ قدیمی، شکاف مدل داده، طرح مقایسهٔ UI). حقایق کلیدی خط مبنا: از ۳۸۰ جدول اصلی فقط ۲۷ (۷٫۱٪) سیم‌کابی شده؛ از ۴۶ Area حدود ۱۵ ماژول هسته‌ای IMPLEMENTED/IN_PROGRESS و بقیه NOT_ANALYZED؛ از ۵٬۳۰۲ SP فقط ۲ رفتار با E2E تصدیق شده؛ تست واحد/فریم‌ورک E2E پایدار وجود ندارد. بازچینش فازهای بعد بر اساس وابستگی‌های واقعی (و نه ترتیب اعلامی قبلی):

| فاز | ماژول | چرا این ترتیب (وابستگی شواهدی) |
|---|---|---|
| ۵ | **زیرساخت تست + تعاریف پایه (ApiBaseInfo)** — 🟡 شروع شد | زیرساخت تست کامل راه‌افتاد (Vitest+Playwright+CI) و گروه اول (جغرافیا) TESTED شد؛ ادامه: گروه‌های P1..P6 طبق `docs/parity/apibaseinfo-matrix.md` |
| ۶ | **ارتباطات (Sms/Email/Telegram)** | ۳۵ جدول بخش-۲ آماده (۱۶ Sms + ۱۱ Email + ۸ CrmTeleg از جمله CrmTelegBot*)؛ آیتم‌های منو با نشان soon جای‌شان خالی است؛ پایهٔ نظرسنجی/باشگاه مشتریان/اعلان‌ها؛ FK ورودی Users زیاد و مستقیم |
| ۷ | **FormBase/DyForms (موتور فرم)** | ۳۵ کنترلر/۷۴ نما/۱۴ جدول متادیتا + ۶۹۹ کوئری ۱۴۳ فرم فعال — رشتهٔ اصلی رفتار فرم‌ها؛ بدون آن فرم‌های پیشرفتهٔ بعدی دوباره‌کاری می‌شوند |
| ۸ | **گزارش‌ساز (۲۷۲ SP گزارشی)** | به دادهٔ فازهای ۶–۷ وابسته است؛ معادل StimulSoft با تصمیم مالک |

| ۱۰ | **یکپارچه‌سازی مالی ۲۲ سامانه + مودیان (Tsp)** | درِ بیرونی‌ترین؛ به فرم‌ها و فروش کامل وابسته؛ متن کامل SPهای تاییدشده با data.zip مالک در دسترس است |
| ۱۱ | **Accounts/Costsheets/PayRolls/Score/Centers/Survey/Targeting** | ماژول‌های مستقل پس از زیرساخت فرم |
| ۱۲ | **موبایل (معادل Mobile.dll — ۸۲ کنترلر)** | پس از تثبیت APIها؛ FCM و QR |

مسدودهای فعال (به مالک گزارش شد): ~~متن کامل ۳٬۱۱۰ SP بریدهٔ جلدهای V5–V8~~ — **حل شد با data.zip مالک (statements.pack — متن کامل هر ۵۹٬۱۲۴ دستور، پوش main/ideal)**؛ اجرای محصول قدیمی برای اسکرین‌شات تازه (اسکرین‌شات واقعی در صورت ارسال، طرح مقایسهٔ UI را فعال می‌کند).
